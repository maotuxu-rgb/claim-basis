# 评估体系说明

本目录包含 `claim-basis` 技能的评估场景，用于检验 SKILL.md 修改前后技能效果是否达标。

每个评估由一对文件组成：`eval-NN-*.json`（输入 `query` + 过程性检查项 `expected_behavior`）与同名 `eval-NN-*-ref.md`（参考分析路径）。七个 `.json` 均已可被程序解析（`python3 -c "import json; json.load(open(f))"`），便于将来做自动比对。当前覆盖：合同编 4 题（Eval-01~04）、物权编 1 题（Eval-05）、侵权编 1 题（Eval-06，反向题）、担保 1 题（Eval-07）。

## 如何使用

目前无自动运行机制。每次评估按以下步骤手动执行：

1. 加载 `claim-basis` 技能（**新建对话**，确保技能已激活，且不带本次讨论上下文——热环境自评偏乐观）
2. 将 `.json` 文件中 `query` 字段的内容原文输入 Claude
3. 对照同名 `-ref.md` 文件中的分析路径，逐条核查 Claude 输出是否满足 `expected_behavior`
4. 按下方「评分标准」判定每条属核心项 / 加分项 / 模板合规项，得出合格结论
5. 记录未满足的项目，作为 SKILL.md 迭代改进的依据

## 评分标准

`expected_behavior` 是**过程性参考，非唯一正确答案**。评分测的是**法律结论正确性 + 方法论健全性**，不是逐字复述参考路径（结论正确但论证路径不同，不应仅因"与 ref 不一致"而扣分）。

每条检查项归入三类之一。归类**按下列标准判断**，而非死记某条编号——`expected_behavior` 数组会随 skill 演进增删，写死清单会很快过时。

### 一、核心项（C）— 一票否决

满足以下任一特征者为核心项，**有一条不过即判不合格**：

- **最终法律结论方向正确**：各候选请求权"成立 / 不成立"的判断结论正确（如 Eval-02 违约方不享有第563条法定解除权；Eval-03 四类请求权均成立且竞合）。
- **预选方法正确**：从法律效果出发预选、候选请求权不少于两项（而非从构成要件倒推）。
- **四步结构齐全**：对每个候选请求权走满"产生要件 → 权利发生抗辩 → 权利消灭抗辩 → 权利行使抗辩权"，不缺段、不错位（如同时履行抗辩须落在"权利行使抗辩权"而非"权利发生抗辩"）。
- **竞合定性正确**：识别竞合类型（规范竞合 / 请求权竞合 / 请求权聚合），并明确"可择一行使、不得重复受偿"。
- **关键特别规范优先关系正确**：如第157条优先于第985条、第615/617条优先于第577条。

### 二、加分项（B）— 反映精细度

不影响结论正确性、但体现分析精细度的项，例如：

- 具体的除斥期间 / 时效起算点提示（如 Eval-01 第152条 1 年起算点的事实争议提示）；
- 句级规范类型差异、跨类规范的双重定性（如 Eval-04 第582条〈主要/抗辩〉、第584条句级差异）；
- 提示参引 vs 类推参引的区分及类推正当性论证（Eval-04 第617条 vs 第467条）；
- 个别条文〈规范类型〉标注的精确度。

> 判别口诀：**做错会导致法律结论错或方法论塌陷的 → 核心项；做错只是"不够细" → 加分项。**

### 三、模板合规项（T）— 独立硬性门槛

每个 `.json` 末条均为模板合规检查（"输出遵循 `references/report-template.md` 结构……"）。这是**独立的一票否决门槛**，对应 SKILL.md §0 的强制约束：正式分析报告须含案情提要时间轴、解题大纲、每个请求权四段齐全、附引用规范表，不得以自创排版替代。

> **例外**：仅当 query 明确要求"口头 / 速答、不要完整报告"时 T 不适用。本目录四个 query 均要求完整分析，故 T 一律适用。

### 合格线

| 评级 | 条件 |
|------|------|
| **不合格** | 任一核心项（C）未过，**或** 模板合规（T）未过 |
| **合格** | C 全过 + T 过 + 加分项（B）通过率 ≥ 70% |
| **良好** | C 全过 + T 过 + 加分项（B）全过 |
